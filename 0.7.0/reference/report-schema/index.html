    Report JSON Schema¶

    Version: 1.2.0

    Every Argus scan produces a JSON report with the following top-level fields.

    Top-level fields¶

    Field Type Description
    schema_version string Schema version identifier. Currently "1.2.0".
    scan_id string UUID v4 unique to this scan.
    generated_at string ISO 8601 timestamp (UTC) when the report was generated.
    cloud string Cloud provider: "aws", "gcp", or "azure".
    accounts_scanned string[] List of account/project/subscription IDs scanned.
    total_estimated_waste_usd number Sum of all findings' estimated_monthly_cost, rounded to 2 decimal places.
    findings_count integer Number of findings in this report.
    findings Finding[] Array of finding objects, sorted by estimated_monthly_cost descending.
    executive_summary string AI-generated 3–5 sentence summary for non-technical stakeholders.
    agent_input_tokens integer Total input tokens consumed by the AI agent during this scan.
    agent_output_tokens integer Total output tokens consumed by the AI agent during this scan.
    estimated_agent_cost_usd number Estimated AI cost for this scan in USD.
    scan_diff ScanDiff Cross-scan comparison data. On the first scan (no previous report found), previous_scan_id is null and every finding counts as new.
    scan_errors object[] Accounts/projects/subscriptions that failed to scan: {account_id, account_name, error}. Empty when all succeeded.
    skipped_resource_types string[] Resource types that were skipped during the scan (for example, GCP asset types whose API isn't enabled).
    registry_warnings string[] Invalid resource-registry entries skipped at load time. Normally empty.
    coverage Coverage \| null What the scan actually analysed. See Coverage object. null when the entrypoint could not provide it. Added in 1.1.0.
    scan_window object \| null Settings actually used: metrics_lookback_days, cost_lookback_days (the effective cost window, at most 14 on AWS), activity_lookback_days, cost_basis, max_resources and max_resources_source (explicit or budget), tags_source (resource_explorer, tagging_api or unavailable), and the LLM economics llm_budget_usd, llm_estimate_usd (computed before the first call), llm_spent_usd, llm_plan (candidates, covered, full_estimate_usd, covered_estimate_usd, order and the printed line: what the budget buys before any call) and llm_calibration (estimated against actual tokens per model call, counts only). With several accounts llm_plan and llm_calibration are per account and left out of the merged block. Added in 1.1.0.
    preflight object \| null Results of the pre-scan environment checks. Added in 1.1.0.
    waste_by_confidence object total_estimated_waste_usd split into high, medium, low and unrated (findings with no confidence). Added in 1.1.0.
    total_is_estimate boolean true unless every finding's cost_basis is billed; headlines then say the total is not billed. Added in 1.1.0.
    cost_summary object Where the dollars come from. waste_by_basis (USD per billed, list_price, model_estimate, unknown; adds up to total_estimated_waste_usd), findings_by_basis (counts), unpriced_findings (findings with no dollar figure; shown as unpriced, never as a billed zero), verified_waste_usd (the billed part), verified_share (billed share of the total, null when the total is 0) and headline_is_verified (true when verified_share is at least 0.5, a provisional threshold, or there is nothing to total). Headlines call the total "billed waste", "estimated waste" or "unverified waste estimate" accordingly. Added in 1.2.0.
    opportunities Opportunity[] Findings grouped into decisions. Every finding is in exactly one. See Opportunity object and Opportunities. Added in 1.2.0.
    opportunity_summary object findings, opportunities, reduction_ratio (null with no findings), lanes (easy and doubt counts), largest_members, other_bucket_members, min_group_size (the size actually used) and max_opportunities. Added in 1.2.0.
    findings_needing_review integer Findings whose review_required is true.
    waste_needs_review_usd number Summed monthly USD of those findings; part of total_estimated_waste_usd, shown separately so it is not read as a safe saving.

    Coverage object¶

    Field Type Description
    discovered integer Billable resources found after exclusion filters.
    analysed integer Resources handed to the AI.
    dropped integer discovered - analysed.
    truncated boolean true when dropped > 0 (the MAX_RESOURCES_PER_SCAN cap bit).
    selection string "cost_desc" (cost data available), "stratified_by_type" (round-robin across types) or "mixed" (multi-account).
    cost_data_available boolean Whether any per-resource cost was returned.
    regions_covered string[] Regions in the discovered inventory.
    types object Per resource type: {discovered, analysed}.
    stop_reason string \| null Why not everything was analysed: "budget", "cap" or "llm_failure"; null when complete.
    skipped_by_reason object Resources not analysed, by reason (budget, cap, llm_failure).
    free_config_skipped integer Free configuration objects (subnets, IAM roles, ...) skipped on purpose; not part of discovered.
    metrics_lost_to_throttling integer Resources whose metrics could not be fetched because the cloud API kept throttling after retries.
    withheld array Model findings left out of the waste total because the evidence could not support them. Each item has resource_id, resource_type, kind (no_metrics, failover_replica, state_unavailable, ami_backed, protected_by_tag, recent_log_activity, activity_unverified, automated_snapshot) and reason. Additive.
    stages object \| null The same scan per stage. rules: evaluated, findings, undecided. gate: mode (off, shadow, on), settled, and in shadow mode settled_but_flagged (settled resources the model flagged anyway; the gate is only safe to enable when this stays 0). model: candidates (what the model still owed after rules), analysed, skipped, stop_reason and order (billed_cost when any billed cost exists; else list_price when a list-price stand-in was available, used for ordering only and never shown as a cost; else type_risk). A partial model pass is read against model.candidates, not against discovered.
    discovery_complete boolean \| null false when a discovery query hit the provider's result limit (AWS Resource Explorer returns at most 1,000 per query; Argus then searches region by region and sets this only if a single region still overflows). null when the adapter does not report it. Added in 1.1.0.

    Finding object¶

    Field Type Description
    resource_id string Cloud-native resource identifier (ARN, self-link, or resource ID).
    resource_type string Registry type ID (e.g. "AWS::EC2::Instance", "sqladmin.googleapis.com/Instance", "microsoft.compute/virtualmachines"). See Resource Types.
    cloud string Cloud provider.
    region string Region or location where the resource exists.
    name string \| null Human-readable name tag, if available.
    estimated_monthly_cost number Estimated monthly cost in USD.
    waste_reason string AI-written explanation of why the resource is considered idle.
    recommendation string AI-written recommended action (delete, resize, tag, etc.).
    priority string "high", "medium", or "low" — assigned by the AI.
    metrics_summary object Key metric signals the AI used to make its decision.
    tags object Resource tags as key-value pairs.
    confidence string \| null "low", "medium" or "high". Forced to low when the metrics behind the finding were unavailable; capped at medium for windows under 90 days. Added in 1.1.0.
    cost_basis string \| null Where the dollar figure comes from: "billed" (Cost Explorer), "list_price" (Argus price catalog, us-east-1 list prices), "model_estimate" (the AI's guess) or "unknown" (no figure). Reports written before 1.1.0 may carry "estimated" or no value; readers treat those as model_estimate when there is a dollar figure and as unknown when there is not. Added in 1.1.0.
    review_required boolean true when a human must check this finding before any ticket, deletion or resize: the name looks like production (prod, prd, production, live, critical, "do not touch") or the estimate is at least $1,000/month with no billed cost behind it. Added in 1.1.0.
    review_reasons string[] Why: prod_like_name, high_unbilled_estimate. Empty when review_required is false.
    detected_by string \| null "model" or "rule:<id>" for a baseline rule. Added in 1.1.0.
    last_activity string \| null ISO 8601 timestamp of the last detected activity, or null.
    scan_time string ISO 8601 timestamp of when the resource was scanned.
    account_id string \| null Account / project / subscription the resource belongs to. Added in 1.0.1; null if it couldn't be attributed.
    account_name string \| null Display name for account_id (from accounts.yaml / ACCOUNTS_CONFIG, else the ID). Added in 1.0.1.
    status string "new" or "recurring", set by cross-scan comparison. Resolved resources aren't in findings; they're listed in scan_diff.resolved_resource_ids.

    ScanDiff object¶

    Field Type Description
    previous_scan_id string \| null Scan ID of the previous report used for comparison.
    new_findings integer Count of findings not present in the previous scan.
    recurring_findings integer Count of findings present in both scans.
    resolved_findings integer Count of findings from the previous scan no longer present.
    resolved_resource_ids string[] Resource IDs that were in the previous scan but not this one.

    Versioning policy¶

    The schema_version field uses semantic versioning:

    • Patch (1.0.x): new optional fields added. Existing consumers are unaffected.
    • Minor (1.x.0): new optional top-level blocks, changed field semantics, or optional fields becoming required.
    • Major (x.0.0): fields removed or renamed. Consumers must update.

    Consumers should check schema_version before parsing and handle unknown versions gracefully.

    Version Change
    1.1.0 (v0.7.0) New optional top-level coverage, scan_window and preflight blocks. Nothing removed or renamed.
    1.0.1 (v0.6.0) Findings gained optional account_id and account_name.
    1.0 Initial schema.

    Opportunity object¶

    Field Type Description
    id string opp- plus 12 hex characters, a hash of key. Stable across scans.
    key object action, family (a resource type, snapshot or other) and tier (flagged, unsure or sure).
    title string Plain template, for example Remove 3 EBS Volumes.
    action string remove, stop, rightsize, retention or review.
    lane string easy or doubt.
    resource_types string[] Types of the members.
    accounts, regions string[] Where the members are.
    owners object[] Up to five {tag, value, count} from the team, owner, project, application, service tags.
    unowned_count integer Members with none of those tags.
    member_count, members integer, string[] All member resource ids, highest cost first.
    savings object low_usd, high_usd, by_basis and unpriced; see Opportunities.
    priority, confidence string Highest member priority; lowest member confidence.
    review_required_count integer Members flagged for human review.
    evidence string[] Plain sentences from the members' own data: how many came from rules and how many from model review, how many have metrics and activity checks, dollars by cost basis, lowest confidence.
    risk string One paragraph: what can go wrong with the action, plus any review flags, low confidence and unpriced members.
    check_first string[] Steps to take before acting, by action and resource family. Templates, not model output.
    risk_reasons string[] Union of the members' review_reasons.
    related string[] Ids of opportunities whose findings name these resources.
